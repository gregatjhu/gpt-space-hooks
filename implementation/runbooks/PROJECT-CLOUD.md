# Project and cloud deployment

For local route tables, existing sessions and repeatable repository setup, start with [assigning a project and its Space](SELECT-PROJECT.md).

For a new or existing cloud session without inherited local guidance, use the [copyable first prompt and acceptance receipt](CLOUD-SESSION-START.md). Keep private destination links in authorized task context. This covers personal coordinator visibility as a separately authorized route as well as project-safe publication; project-only team sessions do not inherit access to a personal hub.

Use [the project profile guide](../work-checkpoint/references/project.md) for schema, audience checks, receipts, original-record bridge, indexes, artifacts and acceptance. The guide ships inside the skill so installed and cloud repository copies remain self-contained.

For each user, create or reuse a checkpoint registry beneath the exact approved project Space. Verify complete sharing and keep the profile outside the shared engine source. The same engine uses `--profile` for this route; default personal mode stays owner-only. Preserve personal authorization/preferences separately.

For a shared repository environment, stage the reviewed `work-checkpoint` directory at `.agents/skills/work-checkpoint` through a reviewed project-repository change. Add the bounded instruction fragment in the profile guide to existing `AGENTS.md` or supported project instructions, preserving existing guidance. Include every helper module and the `references` directory. Use an explicit assigned profile and private store; do not discover profiles or fall back to personal routing.

Local command hooks are not supported in cloud orchestration. Repository skills are available to cloud tasks, while personal local skills are not synced. Setup can stage files, but is not a completion trigger. Verify the fresh cloud task actually receives the skill/instructions and exposes the necessary native Page tools. If Page tools are missing, return the original prepared JSON to the authorized local publisher; do not re-prepare it or copy credentials.

Installation/Space creation does not establish live collaborative acceptance. Follow the two-participant/fresh-cloud-reader test in the profile guide. Verify actual artifact download separately. This source package does not automatically edit project repositories, shared environment settings, sharing policies or schedules.

Official references: [cloud environments](https://learn.chatgpt.com/docs/environments/cloud-environments), [hooks](https://learn.chatgpt.com/docs/hooks), [skill controls](https://learn.chatgpt.com/docs/enterprise/skills).
