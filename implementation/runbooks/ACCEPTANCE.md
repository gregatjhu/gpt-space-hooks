# Per machine acceptance

Record each check as supported, configured, tested, unavailable or untested, with machine name, timestamp, installed runtime version and relevant evidence. Do not treat source code or documentation as execution proof. No remote installer, production access, raw transcripts or new schedules are needed.

1. **Source and scope.** Verify the package manifest/source release signature. Confirm exact Codex home/Python/skill paths and normal installed help. Report the desktop runtime and PATH CLI separately. Confirm intended file reads/edits are authorized.
2. **Local privacy and preservation.** Run both test suites on the target OS. Confirm private store/files through the platform adapter, exact existing config/hook preservation, bounded backups and a repeated hash-checked upgrade. Verify nonowner/symlink/reparse paths are rejected. Windows tests must exercise native NTFS/PowerShell/msvcrt; Linux simulations do not count. Never test against production folders or another user's files.
3. **Two unrelated folders.** With explicit authorization to create disposable chats, start two fresh desktop sessions in distinct disposable directories and two ephemeral bundled-CLI sessions there. Have them report receipt of the installed release guidance, exact helper invocation and actual chat ID from initial context, without tools or transcript access. The catalog/link alone is insufficient. Use a hooks-disabled invocation as a negative control, never a trust bypass or persisted config change. Record missing runtime/model support precisely rather than upgrading automatically.
4. **Stop check.** If enabled and normally trusted, verify actual event execution separately from SessionStart. Unit-test `{}` for a read-only/no-store task, exact prepared identity matching, no filesystem changes, nonblocking output and no raw assistant/transcript input use. Compare named store files before/after a disposable runtime probe; no transcript read is needed. The ordinary helper `stop-check` test proves its behavior, not runtime event dispatch. If runtime exposes no event evidence, leave execution unverified rather than adding monitoring/trace reads without permission.
5. **Identity and freshness.** Prepare a sanitized sample with actual chat ID, explicit machine ID and package version. Use a different chat ID for a fork even in the same folder. Check schema 2 `index`/`status` for distinct groups, unknown legacy identity, observed vs capture times, current delivery and last published record. Do not invent production freshness.
6. **Delivery.** Bind only the existing independently verified owner-only registry. Claim, create, read back exact Markdown, check sharing and acknowledge. Verify pending when Page tools are absent, no retry for uncertain outcomes, preserved historical receipts and a verified immutable index snapshot. Never bulk-publish obsolete pending drafts.
7. **Independent readers.** Obtain an authorized cloud coordinator and separate cloud-task readback of exact new links, record counts, current checkpoint ID, source-dated blockers and owning chats. Readback and task dispatch are different results. Local config/hooks do not propagate automatically to cloud tasks; provide their explicit reader instructions/link separately.
8. **Cadence and rollback.** During changed active work, check that decisions, blockers, tests/deployment and handoffs get timely prepared/published updates at safe boundaries. The five-minute aim and approximately 30-minute active-work guidance are not timer guarantees. Preserve existing nudges. For rollback, stop writing sessions, review exact private backup manifests, restore only this workflow's named changed files through an approved operation, and leave all checkpoint records/receipts intact. Never replace whole config/hooks files blindly after concurrent changes.

Success on one OS does not prove the other adapters. No check authorizes dispatch, credential transfer, software installs, service startup, production changes or new enterprise policy.
