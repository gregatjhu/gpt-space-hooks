# Space checkpoints

Use the exact registry supplied by the user or explicitly assigned to this task. Verify the parent Page, audience and availability of native Page tools before publishing. Personal coordination goes only to an approved owner-only registry. Shared checkpoints contain project facts suitable for the verified audience.

When resuming, find and read the newest applicable verified checkpoint for the actual workstream and owning chat. Follow continuation links where applicable. Report missing context or access and keep source observation dates separate from publication dates.

At a decision, blocker, test or deployment result, or handoff, prepare a short checkpoint with the workstream, actual owning task or chat, machine or runtime when known, repository revision, source observation time, decisions, tests, deployment evidence, action needed, owner and next step. Leave unknown identity or evidence explicit. Omit credentials, raw prompts or transcripts, sensitive records and unrelated personal coordination.

Use the repository's checkpoint delivery protocol and the assigned publisher. If a helper has already prepared a record, preserve that exact revision for the authorized publisher. If the helper is unavailable, return the checkpoint as a draft and state what the publisher needs. Treat publication, content and audience readback, and downstream consumption as separate evidence. Checkpoints confer no execution or dispatch authority.

Use the repository's installer and OS runbooks for local Python helpers and Codex hook setup. This skill provides workflow guidance in ChatGPT.
